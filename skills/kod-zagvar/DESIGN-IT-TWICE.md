# Хоёр удаа зохио

Хэрэглэгч сонгосон гүнзгийрүүлэх нэр дэвшигчид өөр interface-үүдийг судлахыг хүсвэл энэ зэрэгцээ sub-agent-ийн хэв маягийг хэрэглэ. Ousterhout-ийн "Design It Twice" (хоёр удаа зохио) санаанд суурилсан: анхны санаа чинь хамгийн шилдэг нь байх магадлал бага.

[SKILL.md](SKILL.md)-ийн нэр томъёог ашиглана: **module**, **interface**, **seam**, **adapter**, **leverage**.

## Явц

### 1. Асуудлын хүрээг тодорхойл

Sub-agent эхлүүлэхээс өмнө сонгосон нэр дэвшигчийн асуудлын хүрээг хэрэглэгчид зориулж тайлбарла:

- Аливаа шинэ interface хангах ёстой хязгаарлалтууд
- Түүний найдах хамаарлууд ба тэд аль ангилалд багтах ([DEEPENING.md](DEEPENING.md)-г үз)
- Хязгаарлалтыг тодорхой болгох ойролцоо жишээ код: санал биш, зүгээр л хязгаарлалтыг бодитой харуулах арга

Үүнийг хэрэглэгчид үзүүлээд, шууд 2-р алхам руу шилж. Sub-agent-ууд зэрэгцэн ажиллаж байх зуур хэрэглэгч уншиж, бодно.

### 2. Sub-agent-уудыг эхлүүл

3 ба түүнээс дээш sub-agent-ыг зэрэгцээ, тус бүрийг шинэ context window-оор эхлүүл. Тус бүр гүнзгийрүүлсэн module-д **эрс өөр** interface гаргах ёстой.

Sub-agent бүрд тусдаа техникийн даалгавар өг (файлын зам, coupling-ийн дэлгэрэнгүй, [DEEPENING.md](DEEPENING.md)-ийн хамаарлын ангилал, seam-ийн ард юу байх). Энэ даалгавар нь 1-р алхмын хэрэглэгчид зориулсан тайлбараас тусдаа. Agent бүрд өөр дизайны хязгаарлалт өг:

- Agent 1: "Interface-ийг хамгийн бага болго: дээд тал нь 1–3 орох цэг. Орох цэг бүрийн leverage-ийг хамгийн их болго."
- Agent 2: "Уян хатан байдлыг хамгийн их болго: олон хэрэглээ ба өргөтгөлийг дэмж."
- Agent 3: "Хамгийн түгээмэл дуудагчид зориулж оновчлох: үндсэн тохиолдлыг маш энгийн болго."
- Agent 4 (тохирох бол): "Seam дамнасан хамаарлуудын хувьд ports & adapters-ийг тойруулж зохио."

Даалгаварт [SKILL.md](SKILL.md)-ийн нэр томъёо ба GLOSSARY.md-ийн нэр томъёог хоёуланг нь оруул. Тэгвэл sub-agent бүр архитектурын хэл ба төслийн domain-ий хэлтэй нийцүүлж нэрлэнэ.

Sub-agent бүр гаргана:

1. Interface (type, method, параметр, мөн invariant, дараалал, алдааны горим)
2. Дуудагчид үүнийг яаж хэрэглэхийг харуулсан жишээ
3. Implementation seam-ийн ард юуг нуух
4. Хамаарлын стратеги ба adapter-ууд ([DEEPENING.md](DEEPENING.md)-г үз)
5. Давуу ба сул тал: leverage хаана өндөр, хаана нимгэн

### 3. Танилцуулж, харьцуул

Хэрэглэгч тус бүрийг ойлгож авахаар дизайнуудыг нэг нэгээр нь танилцуул, дараа нь текстээр харьцуул. **Depth** (interface дээрх leverage), **locality** (өөрчлөлт хаана төвлөрөх), **seam-ийн байршлаар** нь ялгаж үз.

Харьцуулсны дараа өөрийн зөвлөмжөө өг: аль дизайн хамгийн хүчтэй гэж бодож байгаа, яагаад. Өөр дизайнуудын хэсгүүд сайн нийлэх бол холимог хувилбар санал болго. Тодорхой байр суурьтай бай: хэрэглэгч сонголтын цэс биш, хүчтэй дүгнэлт хүсэж байна.
