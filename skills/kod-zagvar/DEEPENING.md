# Гүнзгийрүүлэх

Shallow module-уудын бөөгнөрлийг хамаарлыг нь харгалзан аюулгүй гүнзгийрүүлэх арга. [SKILL.md](SKILL.md)-ийн нэр томъёог ашиглана: **module**, **interface**, **seam**, **adapter**.

## Хамаарлын ангилал

Гүнзгийрүүлэх нэр дэвшигчийг үнэлэхдээ түүний хамаарлуудыг ангил. Ангилал нь гүнзгийрүүлсэн module-ийг seam-ээр нь дамжуулан хэрхэн test хийхийг тодорхойлно.

### 1. Процесс доторх (in-process)

Цэвэр тооцоолол, санах ой дахь төлөв, I/O байхгүй. Үргэлж гүнзгийрүүлж болно: module-уудыг нийлүүлж, шинэ interface-ээр нь шууд test хий. Adapter хэрэггүй.

### 2. Локал орлогчтой (local-substitutable)

Test-д зориулсан локал орлогчтой хамаарал (Postgres-ийн оронд PGLite, санах ой дахь файлын систем). Орлогч байвал гүнзгийрүүлж болно. Гүнзгийрүүлсэн module-ийг test suite дотор орлогчийг ажиллуулж test хийнэ. Seam дотоод; module-ийн гадаад interface дээр port байхгүй.

### 3. Алсын боловч өөрийн (Ports & Adapters)

Сүлжээний цаана байгаа өөрийн service-үүд (microservice, дотоод API). Seam дээр **port** (interface) тодорхойл. Deep module логикийг эзэмшинэ; дамжуулалт (transport) нь **adapter** болж гаднаас орж ирнэ. Test нь in-memory adapter, production нь HTTP/gRPC/queue adapter хэрэглэнэ.

Зөвлөмжийн хэлбэр: *"Seam дээр port тодорхойлж, production-д HTTP adapter, test-д in-memory adapter хэрэгжүүл. Тэгвэл сүлжээгээр тарааж deploy хийсэн ч логик нэг deep module-д байна."*

### 4. Жинхэнэ гадаад (Mock)

Чиний удирдаж чадахгүй гуравдагч талын service-үүд (Stripe, QPay, Twilio гэх мэт). Гүнзгийрүүлсэн module гадаад хамаарлыг гаднаас орж ирэх port хэлбэрээр авна; test нь mock adapter өгнө.

## Seam-ийн сахилга

- **Нэг adapter бол таамаг seam. Хоёр adapter бол жинхэнэ seam.** Наад зах нь хоёр adapter (ихэвчлэн production + test) үндэслэлтэй биш бол port бүү нэм. Ганц adapter-тай seam бол зүгээр л илүүдэл тойруу зам (indirection).
- **Дотоод seam ба гадаад seam.** Deep module interface дээрх гадаад seam-ээс гадна дотоод seam-тэй (implementation-дээ хувийн, өөрийн test-үүддээ хэрэглэдэг) байж болно. Test хэрэглэдэг гэдэг шалтгаанаар дотоод seam-ийг interface-ээр бүү ил гарга.
- **Port-ийг технологиор биш, чадвараар нь нэрлэ.** `StripeClient` биш, `PaymentGateway`. Тэгвэл технологи солиход зөвхөн adapter өөрчлөгдөнө.

## Test-ийн стратеги: давхарлах биш, соль

- Гүнзгийрүүлсэн module-ийн interface дээр test бий болмогц shallow module-уудын хуучин unit test хог болно; устга.
- Шинэ test-үүдийг гүнзгийрүүлсэн module-ийн interface дээр бич. **Interface бол test-ийн гадаргуу**.
- Test нь дотоод төлөвийг биш, interface-ээр харагдах үр дүнг шалгана.
- Test нь implementation-ийг биш, зан төлөвийг тодорхойлдог тул дотоод refactor-ыг даван гарах ёстой. Implementation өөрчлөгдөхөд test өөрчлөгдөх шаардлагатай бол тэр test interface-ийг давж шалгаж байна.
- **Эхлээд бэхэл, дараа нь зөө.** Бөөгнөрөлд test байхгүй бол одоогийн зан төлөвийг бэхлэх хэдэн test эхлээд бич. Нэг удаад нэг бөөгнөрөл гүнзгийрүүл; бүгдийг нэг дор бүү дахин бич.
