Agent уншдаг аливаа баримт бичгийг бичих лавлах: skill, `AGENTS.md` / `CLAUDE.md`, заагчаар хүрдэг doc. Савлагаа нь өөр, бичих арга нь ижил: нэг ижил хөшүүрэг (lever) тус бүрийг урьдчилан таамаглахуйц болгоно, учир нь agent ажиллах бүртээ ижил гаралт биш, ижил _процесс_-оор явдаг.

Бичиж буй баримт бичиг чинь skill бол frontmatter, дуудах аргын сонголт, router skill-ийн талаар [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)-г унш.

## Context pointer

**Context pointer** (context-ийн заагч) гэдэг нь agent-ийн context-д байгаа, context-ээс гадуурх материалыг нэрлэж, түүнд хүрэх нөхцөлийг агуулсан ишлэл. Skill-ийн description бол нэг жишээ; `AGENTS.md` дахь doc нэрлэсэн мөр ч ижил зүйл. Agent материалд хэзээ, хэр найдвартай хүрэхийг заагчийн зорилт биш, _үг хэллэг_ нь шийднэ. Заавал хэрэгтэй материал сул бичигдсэн заагчийн цаана байвал энэ нь variance bug (ажиллах бүрт өөр үр дүн өгдөг алдаа): эхлээд үг хэллэгийг хурцал, хурцлах нь бүтэхгүй бол л материалыг файлд шууд оруул.

Заагч хоёр ажил хийнэ: материал юу болохыг хэлнэ, түүнд хүргэх ёстой **салаа**-г (branch) жагсаана (салаа гэдэг нь баримт бичгийн шийддэг тусдаа тохиолдол, тиймээс өөр өөр ажиллалт түүгээр өөр өөр замаар явна). Үргэлж ачаалагдсан заагчийн үг бүр turn бүрт зардал гаргадаг тул body-оос ч илүү хатуу тайрах ёстой:

- **Leading word-оо урд нь тавь**: заагч бол түүний өдөөх ажлаа хийдэг газар.
- **Салаа бүрт нэг өдөөгч.** Нэг салааг өөр нэрээр дахин нэрлэсэн ижил утгатай үгс бол хоёр бичсэн нэг салаа; нэгтгээд зөвхөн жинхэнэ ялгаатай салаануудыг үлдээ.
- **Body аль хэдийн агуулж буй танилцуулгыг (identity) хас.**

## Хоёр ачаалал

Нэмж буй баримт бичиг, заагч бүр хоёр төсвийн нэгийг зарцуулна:

- **Context load** (context-ийн ачаалал) бол үргэлж ачаалагдсан материалын agent-ийн window-д учруулах зардал: `AGENTS.md`-ийн мөр, skill-ийн description, turn бүрт context-д сууж, ажиллах эсэхээс үл хамааран token, анхаарал зарцуулдаг бүх зүйл.
- **Cognitive load** (оюуны ачаалал) бол хүнд учруулах зардал: ямар баримт бичиг байгаа, хэзээ алийг нь авах. Хүн өөрөө индекс нь. Багасгах ёстой зардал биш: энэ бол хүний эрх мэдлийн үнэ; хүний шүүлт чухал газар зарцуул, чухал биш газраас хас.

Зөвхөн заагчаар хүрдэг материал заагчийн нэг мөрийн үнээр context load-оос мултардаг; заагчгүй материал бүхэлдээ cognitive load дээр явна.

## Мэдээллийн шатлал

Баримт бичиг хоёр төрлийн агуулгаас бүтнэ: **алхам** (step: agent-ийн дарааллаар хийх үйлдлүүд) ба **лавлах** (reference: хэрэгтэй үед харах тодорхойлолт, дүрэм, баримт). Хоёр нь чөлөөтэй холилдоно: бүгд алхам (жор), бүгд лавлах (review-ийн дүрмүүд, энэ skill), эсвэл хоёулаа. Гол шийдвэр бол хэсэг бүр **мэдээллийн шатлал** (information hierarchy) дээр хаана суух вэ: agent-д хэр яаралтай хэрэгтэйгээр эрэмбэлсэн шат:

1. **Файл доторх алхам** бол үндсэн давхарга: agent юу хийх, ямар дарааллаар.
2. **Файл доторх лавлах** хэрэгтэй үед харагдана. Ихэвчлэн жинхэнэ хавтгай, тэнцүү зэрэглэлийн багц (review-ийн бүх дүрэм нэг шатанд), энэ бол буруугийн шинж биш, зөв зохион байгуулалт.
3. **Disclosed reference** (тусад нь гаргасан лавлах) тусдаа файлд байж, context pointer-оор хүрдэг, заагч ажиллах үед л ачаалагдана. Нэг folder доторх хөрш файлаас эхлээд хаана ч байж болох, ямар ч баримт бичиг зааж болох бүрэн гадаад лавлах хүртэл хамарна.

Хэт бага доош түлхвэл дээд хэсэг хавдана; хэт их түлхвэл agent-д үнэхээр хэрэгтэй материалыг нууна. Энэ хурцадмал байдал л бүх шийдвэр.

**Progressive disclosure** (аажмаар нээх) бол шатаар доош хийх нүүдэл (үндсэн файлаас гарч заагчийн цаана орох), ингэснээр дээд хэсэг уншигдахуйц үлдэнэ. Юуны өмнө token хэмнэлт биш: шатлалыг ингэж хамгаалдаг. Салаалалт бол хамгийн цэвэр шалгуур: салаа бүрт хэрэгтэйг файлд шууд оруул, зөвхөн зарим салааны хүрдэг зүйлийг заагчийн цаана түлх. Баримт бичигт алхам байхад, гадагш гаргах ёстой лавлах файл дотор үлдвэл алхмуудыг дарж, тэдэнд анхаарал хандуулахыг зоос шидэлт болгоно: энэ бол зөвхөн уншигдах байдлын биш, variance-ийн хөшүүрэг.

**Co-location** (хамт байршуулах) бол файл доторх хамтрагч нь: шат нь хэсэг _хэр доор_ суухыг шийддэг бол co-location нь тэнд очсоных нь дараа _хажууд нь юу суухыг_ шийднэ. Ойлголтын тодорхойлолт, дүрэм, анхааруулгыг тараалгүй нэг гарчиг дор байлга, ингэснээр нэг хэсгийг уншихад хөршүүд нь дагаж ирнэ. Шалгуур: баримт бичиг agent-д зориулж бичсэн documentation шиг уншигдах ёстой. Бүлэглэсэн материал тэгж уншигдана; тарсан материал тэгж уншигдахгүй. (Давхардлаас ялгаатай: давхардал нэг утгыг хоёр газар давтдаг; тараалт нэг утгыг олон газар хэсэглэдэг.)

**Sprawl** (хэт тэлэлт) бол энд гардаг алдаа: мөр бүр амьд, давтагдашгүй байсан ч зүгээр л хэт урт баримт бичиг. Илүүдэл дээр анхаарал сийрэгжиж, нэмэлт мөр бүр хамааралтай байлгах ёстой бас нэг мөр болно. Эмчилгээ нь шат: лавлахыг заагчийн цаана гарга, салаа эсвэл дарааллаар хуваа, ингэснээр зам бүр зөвхөн хэрэгтэйгээ авч явна.

## Алхам ба дуусгах шалгуур

Алхам бүр **completion criterion** (дуусгах шалгуур)-аар төгсдөг: ажил дууссаныг agent-д хэлдэг нөхцөл. Хоёр шинж нь түүнийг хөшүүрэг болгоно:

- **Тодорхой байдал**: agent дууссан, дуусаагүйг ялгаж чадах уу? Бүрхэг хязгаар ("ойлголтод хүрсэн") **premature completion**-ийг (эрт дуусгах) урина: алхмыг жинхэнэ дуусахаас өмнө төгсгөж, анхаарал _дуусгах_ руу гулсана. Харагдаж буй цаашдын алхмууд (**post-completion steps**) татах хүчийг өгдөг; шалгуурын тодорхой байдал эсэргүүцлийг өгнө. Дарааллаар хамгаал: **эхлээд хязгаарыг хурцал** (нэг газарт, хямд); зөвхөн энэ нь угаасаа бүрхэг _бөгөөд_ яарах байдлыг ажигласан үед л дарааллыг хувааж хожмын алхмуудыг нуу. Нуух нь зөвхөн жинхэнэ context-ийн заагаар (handoff эсвэл subagent руу илгээх) ажилладаг; inline дуудлага хожмын алхмуудыг context-д үлдээж, юуг ч цэвэрлэхгүй.
- **Шаардлага**: хэр ихийг шаардах. "Өөрчлөгдсөн model бүрийг тооцсон" нь "өөрчлөлтийн жагсаалт гарга"-аас илүү нягт ажил шаарддаг. Шаардлага **legwork**-ийг (agent ажлын дотор хийдэг ухалт, тусдаа алхам болж бичигдээгүй ч үг хэллэгт нуугдсан) хөдөлгөдөг бөгөөд алхамд хязгаарлагдахгүй: "алхам бүрийг хийсэн" нь дарааллыг холбодог шиг "дүрэм бүрийг хэрэглэсэн" нь хавтгай лавлахын биеийг холбодог; бүхэлдээ лавлах баримт бичиг ч бүрэн гүйцэд байдлын шаардлагыг ингэж авч явна.

Хамгийн хүчтэй шалгуур нь шалгаж болохуйц бөгөөд бүрэн гүйцэд байдаг.

## Хэзээ хуваах вэ

Нэг баримт бичгийг хоёр болгох нь хоёр ачааллын нэгийг зарцуулна, тиймээс тайралт үнэ цэнэтэй үед л хуваа:

- **Дарааллаар**: цаашдын алхмууд нь agent-ийг урд нь байгаа алхмыг яаруулахаар уруу татдаг алхмуудын цувааг хуваа. Тэднийг харагдахгүй байлгах нь одоогийн ажилд илүү legwork хийлгэнэ. Эсрэгээс нь болгоомжил: дарааллуудыг нэгтгэх нь алхам бүрд дараагийн алхмуудыг нь ил гаргаж, эрт дуусгахыг урина.
- **Дуудлагаар** (skill-д онцгой): [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)-г үз.

## Leading word

**Leading word** (тэргүүлэх үг) гэдэг нь model-ийн pretraining-д аль хэдийн амьдардаг, agent баримт бичгийг ажиллуулж байхдаа түүгээр сэтгэдэг товч ойлголт (_lesson_, _fog of war_, _tracer bullets_). Өгүүлбэр биш, token болж давтагдахдаа тархсан тодорхойлолт хуримтлуулж, model-ийн аль хэдийн мэддэг prior-уудыг дайчлан хамгийн цөөн token-оор зан төлөвийн бүхэл бүсийг бэхэлнэ. Өөрөө зохиосон үг тодорхой тодорхойлбол ажилладаг ч зохиомол үг ямар ч prior дайчлахгүй: pretraining-ийн үг үнэгүй өгдгийг чи тодорхойлолтын token-оор төлнө; эхлээд байгаа үгээ хай. (Pretraining-д хамгийн хүчтэй нь ихэвчлэн англи үг байдаг тул Монгол текст дотор англи leading word-ийг хэвээр нь үлдээ.)

Хоёр удаа бэхэлдэг. Body-д _гүйцэтгэлийг_: үг гарах бүрт agent ижил зан төлөвт хүрдэг, хавтгай лавлах дотор бол хайх зүйлийн ангилалд анхаарлыг төвлөрүүлнэ. Заагчид _дуудлагыг_: ижил үг чиний prompt, doc, codebase-д амьдрахад agent тэр нийтлэг хэлийг материалтай холбож, түүнд илүү найдвартай хүрнэ.

Leading word-оор refactor хийх боломжийг ангуучил: гурван газарт задалж бичсэн гурвал, нэг санааг заахын тулд бүтэн өгүүлбэр зарцуулсан заагч. Тус бүр нэг token болж агшихыг гуйж буй хэсэг:

- "fast, deterministic, low-overhead" (хурдан, тогтмол, бага зардалтай) → _tight_ (_tight_ loop).
- "a loop you believe in" (итгэж болох давталт) → _red_, бүрхэг шалгуурыг хоёр л төлөвтэй ажиглагдах зүйл болгоно (давталт bug дээр _red_ болдог, эсвэл болдоггүй).

Чи хоёр удаа хожно: цөөн token, бас agent-д бодлоо өлгөх илүү хурц дэгээ. Баримт бичиг бүр leading word-оор солигдож болох давталт агуулж байгаа гэж үз. Яв, ол.

**Negation** (үгүйсгэл) бол энэ хөшүүргийн хажуугийн алдаа: хоригоор жолоодох нь хориглосон зан төлөвийг context руу чирж, түүнийг _бага_ биш _илүү_ хүртээмжтэй болгоно. _Заан бүү бод_ гэвэл толгойд зөвхөн заан л үлдэнэ: үгүйсгэл бол хүчтэй идэвхжсэн ойлголтод дарагддаг сул тодотгол тул хориг хагас нь тэр зүйлийг хий гэсэн заавар шиг уншигдана. **Эерэгээр** prompt бич: зорилтот зан төлөвийг хэл ("нэг мөрт comment бич"), ингэснээр хориглосон нь хэзээ ч дурдагдахгүй. Хориг нь эерэгээр илэрхийлж чадахгүй хатуу хамгаалалт (guardrail) байх үед л байр сууриа олно; тэр үед ч анхаарал юу хийх дээр буухын тулд эерэг зорилттой нь хос болго.

## Тайралт

- Утга бүрийг **single source of truth**-д (цорын ганц үнэний эх) байлга: нэг эрх мэдэлтэй газар, ингэснээр зан төлөвийг өөрчлөх нь нэг газрын засвар болно. **Duplication** (давхардал: нэг утга нэгээс олон газар) засвар үйлчилгээ, token зардалтай бөгөөд утгын шатлал дахь байрыг жинхэнэ зэргээс нь дээш хөөрөгдөнө. (Leading word-ийн санамсаргүй эсрэг тал: leading word утгыг биш, token-ыг санаатай давтдаг.)
- **Орчин** ч бас үнэний эх (`package.json` script, config файл, folder-ийн бүтэц, `--help` гаралт), түүнийг дахин хэлдэг баримт бичиг бол **cache**: хайлтын хуулбар, хайлт үнэтэй үед л ачааллаа зөвтгөнө. Agent хараад олж чадахгүй зүйлийг cache хий: бичигдээгүй дүрэм, сонголтын цаад шалтгаан, ямар ч config хүлээн зөвшөөрдөггүй онцгой бэрхшээл (gotcha). Нэг файл, нэг командын хайлтыг хуучирч чадахгүй газарт нь, орчинд нь үлдээ.
- Мөр бүрийг **relevance**-аар (хамаарал) шалга: баримт бичгийн хийдэг зүйлд одоо ч хамааралтай юу? Мөр хоёр замаар хамаарлаа алдана: ажилд хэзээ ч хамааралгүй байх (зүгээр тайлбар, эсвэл гадагш гаргах ёстой салаа), эсвэл тайлбарласан зан төлөв, ертөнц өөрчлөгдөхөд хуучрах. Богино баримт бичгийг хамааралтай байлгахад амар. Тайралтын дадал байхгүй бол **sediment** (тунадас) нь default хувь заяа: нэмэх нь аюулгүй, хасах нь эрсдэлтэй санагддаг тул хуучин давхаргууд тунадасжиж, эцэст нь юу амьд байгааг олохын тулд тэдгээрийг өрөмдөх хэрэгтэй болно.
- **No-op**-ийг өгүүлбэр бүрээр ангуучил: model default-аараа аль хэдийн дагадаг заавар юу ч хэлэхгүйн тулд ачаалал төлдөг. Шалгуур (default-тай харьцуулахад зан төлөвийг өөрчлөх үү?) уншигчаас биш model-оос хамаардаг: no-op-ийн талаар маргаж буй хоёр хүн default-ийн талаар маргаж байгаа бөгөөд мэтгэлцээгээр биш, баримт бичгийг ажиллуулж шийднэ. Өгүүлбэр тэнцэхгүй бол үгээс нь тайрахын оронд бүх өгүүлбэрийг устга. Шалгуур leading word-ийг ч дүгнэдэг: default-ийг ялахад хэт сул үг (agent аль хэдийн нэлээд нягт байхад _be thorough_ буюу "нягт бай") бол no-op, засвар нь өөр арга биш, илүү хүчтэй үг (_relentless_ буюу "зогсолтгүй").
