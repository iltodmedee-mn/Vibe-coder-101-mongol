# ADR-ын хэлбэр

ADR-ууд `docs/adr/`-д байрлаж, дараалсан дугаартай байна: `0001-slug.md`, `0002-slug.md` гэх мэт.

`docs/adr/` folder-ийг хэрэгтэй болсон үед нь л үүсгэ: эхний ADR хэрэгтэй болоход.

## Загвар

```md
# {Short title of the decision}

{1-3 sentences: what's the context, what did we decide, and why.}
```

Ингээд л болоо. ADR ганц догол мөр байж болно. Үнэ цэнэ нь хэсгүүдийг бөглөхөд биш, шийдвэр гарсан *гэдгийг* болон *яагаад* гэдгийг тэмдэглэхэд оршино.

## Нэмэлт хэсгүүд

Эдгээрийг бодит үнэ цэнэ нэмэх үед л оруул. Ихэнх ADR-д хэрэггүй.

- **Status** талбар, файлын эхний YAML хэсэгт (`proposed | accepted | deprecated | superseded by ADR-NNNN`): шийдвэрийг дахин эргэж харах үед хэрэгтэй
- **Авч үзсэн сонголтууд**: татгалзсан сонголтууд нь санаж үлдэх үнэ цэнэтэй үед л
- **Үр дагавар**: илэрхий биш, цаашид гарах нөлөөг онцлох шаардлагатай үед л

## Дугаарлалт

`docs/adr/`-аас хамгийн их дугаарыг олоод нэгийг нэм.

## ADR-ыг хэзээ санал болгох вэ

Дараах гурвуулаа үнэн байх ёстой:

1. **Буцаахад хэцүү**: дараа нь бодлоо өөрчлөх өртөг их
2. **Тайлбаргүй бол гайхмаар**: ирээдүйд кодыг уншиж буй хүн "яг юуны тулд ингэж хийсэн юм бол?" гэж гайхна
3. **Бодит trade-off-ын үр дүн**: жинхэнэ өөр сонголтууд байсан, тодорхой шалтгаанаар нэгийг нь сонгосон

Шийдвэрийг буцаахад амархан бол алгас: зүгээр л буцаана. Гайхмаар биш бол хэн ч яагаад гэж асуухгүй. Бодит өөр сонголт байгаагүй бол "ойлгомжтой замаар явсан"-аас өөр тэмдэглэх зүйл алга.

### Юу тэнцэх вэ

- **Архитектурын хэлбэр.** "Бид monorepo ашигладаг." "Write model нь event-sourced, read model нь Postgres руу project хийгддэг."
- **Context-уудын хоорондын холболтын хэв маяг.** "Захиалга ба Төлбөр нь synchronous HTTP биш, domain event-ээр харилцана."
- **Түгжрэл (lock-in) үүсгэдэг технологийн сонголт.** Database, message bus, auth provider, төлбөрийн систем (QPay гэх мэт), deploy хийх газар. Library бүр биш: солиход гурван сар орчим шаардах хэмжээнийх л.
- **Хил хязгаар, хамрах хүрээний шийдвэр.** "Үйлчлүүлэгчийн өгөгдөл Үйлчлүүлэгч context-д харьяалагдана; бусад context зөвхөн ID-гаар нь иш татна." Тодорхой "үгүй" гэсэн шийдвэр "тийм"-тэй адил үнэ цэнэтэй.
- **Ойлгомжтой замаас санаатай гажсан шийдвэр.** "X учраас ORM-ын оронд SQL-ийг гараар бичнэ." Ухаалаг уншигч эсрэгээр нь таамаглах бүх зүйл. Эдгээр нь дараагийн хүнийг (эсвэл AI-г) санаатай хийсэн зүйлийг "засах"-аас сэргийлнэ.
- **Кодонд харагддаггүй хязгаарлалт.** "Хууль, журмын шаардлагаас болж AWS ашиглаж болохгүй." "Хамтрагчийн API-ийн гэрээгээр хариу өгөх хугацаа 200ms-ээс бага байх ёстой."
- **Татгалзсан шалтгаан нь илэрхий биш сонголтууд.** GraphQL-ийг авч үзээд нарийн шалтгаанаар REST сонгосон бол тэмдэглэ; эс тэгвээс зургаан сарын дараа хэн нэгэн GraphQL-ийг дахин санал болгоно.

### Анзаарах дохио

Хэрэглэгч "ADR" гэж хэлэхгүй байж болно. Дараах мэт үг сонсвол дээрх гурван шалгуураар шалга: "X-ээр явъя", "Y-ийн оронд X ашиглая", "энэ trade-off нь үнэ цэнэтэй, учир нь...". Хэрэглэгч "яагаад X-ийг сонгосон юм бэ?" гэж асуувал эхлээд `docs/adr/`-аас хай.
