# Wizard

**Wizard** гэдэг нь гараар хийхэд уйтгартай, AI-д дахин дахин тайлбарлахад ч уйтгартай гар ажиллагааг хүнээр алхам алхмаар хийлгэдэг bash script. URL бүрийг нээж, юуг дарж, юуг хуулахыг яг хэлж, утгуудыг барьж аваад зохих газарт нь (`.env`, GitHub secret) бичиж, үе шат бүрт баталгаажуулж, хэдэн үе шат үлдсэнийг харуулна. Гуравдагч талын service тохируулах, нэг удаагийн migration ажиллуулах, эсвэл төслийг нэг төлвөөс нөгөөд шилжүүлж болно.

Таатай UX-ийг [template.sh](template.sh) аль хэдийн шийдсэн: үе шат бүрийн явц, баталгаажуулах хаалт, платформ бүрт (WSL-ийг оруулаад) URL нээх, secret-ийг нуун оруулах, `.env`-д idempotent (дахин ажиллуулахад ижил үр дүнтэй) upsert хийх, `gh secret`/`gh variable`-ээр бичих, төгсгөлийн хураангуй. **Чиний ажил бол зөвхөн гар ажиллагааны хүрээг тогтоож, үе шатуудыг нь бичих.** `STAGES` тэмдэгээс дээших library wizard бүрт адилхан; энэ тогтвортой байдал л гол нь: түүнийг хэзээ ч гараар бүү засварла.

Wizard анхдагчаар түр зуурынх: нэг удаа ажиллуулахаар бүтээгдэж, scratch эсвэл `scripts/` замд хадгалагдаж, ажил дуусахаар устгагдана. Хэрэглэгч repo-д байх, давтан ашиглах setup-ийн зам хүсвэл л commit хий.

## Явц

### 1. Гар ажиллагааны хүрээг тогтоо

Хүний хийх ёстой гар алхам бүр, замдаа барьж авах утга бүрийг тодорхойл. Эхлээд repo-гоо унш, хоосон юм асууж бүү эхэл:

- Setup-д: `.env`, `.env.example`, `.env.*`, `README`, `docker-compose*`, framework-ийн тохиргоо, мөн `.github/workflows/*` (`secrets.*` / `vars.*` ишлэл бүр бол wizard-ийн гаргах ёстой утга).
- Migration эсвэл шилжилтэд: одоогийн төлөв, зорилтот төлөв, мөн тэдгээрийн хоорондох буцаах боломжгүй үйлдлүүд.

Дараа нь үе шатуудын дараалсан жагсаалт болон тус бүрийн гаргах утгуудыг хэрэглэгчид харуулаад батлуул: тэд нэмж, хасаж, дарааллыг өөрчилж болно.

**Дууссан гэж үзэх нь:** үе шат бүр дарааллаараа нэртэй, барьж авах утга бүрийн хувьд (a) хүн түүнийг хаанаас авах, (b) хаана бичигдэх (`.env`, GitHub secret, хоёулаа, эсвэл хаана ч үгүй; зарим үе шат зөвхөн үйлдэл байдаг), (c) нууц (нуун оруулна) эсвэл ил эсэхийг мэдэж байх.

### 2. Үе шат бүрийн замыг зурагла

Үе шат бүрт хүний дагах яг замыг бич: ямар URL нээх, тэнд юу хийх, утга хаана харагдах, аль хувьсагчийг дүүргэх. Жишээ нь "Dashboard → Developers → API keys → Reveal test key → хуул". Одоогийн UI эсвэл яг командыг үнэхээр мэдэхгүй бол тэгж хэлээд хэрэглэгчээс асуу эсвэл docs-ийг шалга: байхгүй байж болох алхмыг хэзээ ч бүү зохио.

**Дууссан гэж үзэх нь:** үе шат бүр танихгүй хүн ч дагаж чадах тодорхой заавартай болсон байх.

### 3. Wizard-аа бич

`template.sh`-г зорилтот зам руу хуул. Жишээ үе шатыг алхам бүрт нэг `stage`-ээр, хамаарлын дарааллаар соль. Library-ийн туслахуудыг ашигла: `stage`, `say`/`step`, `open_url`, `ask`/`ask_secret`, `write_env`, `set_secret`/`set_var`, `pause`/`confirm`. `TOTAL_STAGES`-г бичсэн үе шатуудынхаа тоонд тохируул.

Template-ийн тогтоосон түвшнийг барь: утгыг нь асуухаасаа өмнө URL-аа нээ, нууц бүхэнд `ask_secret` ашигла, хадгалах утга бүрийг `write_env` хий, зөвхөн CI-д үнэхээр хэрэгтэй утгуудыг `set_secret` хий, буцаах боломжгүй үйлдэл бүрийн өмнө `confirm` хий. `stage` бүр дэлгэцийг цэвэрлэж зөвхөн одоогийн алхмыг харуулдаг: үе шат бүрийг нэг төвлөрсөн ажилтай байлга, тэгвэл хүнд хэрэгтэй юу ч дээш гүйлгэгдэж алга болохгүй. Тэмдэгээс дээших library-д бүү хүр.

### 4. Шалгаад хүлээлгэж өг

- `bash -n <script>`; боломжтой бол `shellcheck` ажиллуул.
- `chmod +x <script>`.
- Эхнээс нь дуустал өөрөө бүү ажиллуул: browser нээж, хүний оролтыг хүлээж гацна. Оронд нь статикаар мөрдөж шалга: 1-р алхмын утга бүр барьж авагдаж, 1-р алхамд заасан газарт очиж байгаа эсэх, мөн `set_secret`-ийн нэр бүр CI дахь `secrets.*` ишлэлтэй яг таарч байгаа эсэх.
- Хэрэглэгчид яаж ажиллуулахыг хэл. Давтан ашиглах setup-ийн зам бол commit хийгээд README-ээс холбоос өг, тэгвэл дараагийн хүн AI-аас асуухын оронд script-ийг ажиллуулна.
