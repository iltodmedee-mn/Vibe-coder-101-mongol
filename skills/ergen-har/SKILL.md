Хэрэглэгч **retrospective** хийхийг хүссэн. Чи дараагийн ажиллагаа илүү сайн явахын тулд кодын agent-ийн **орчныг** сайжруулах санал гаргана.

## Алхмууд

1. Бичих хэв маягийн зааврыг авахын тулд Skill tool-оор `agent-zaavar`-ыг дууд.

2. Хэрэглэгчийн заасан session-ий анхдагч эх сурвалжийг унш. Үүний тулд энэ машин дээрх session log-уудаас хайх хэрэгтэй байж магадгүй. Хэрэглэгч session заагаагүй бол одоогийнхыг ав.

3. Сайжруулах боломжуудыг дараах ангиллаар хай.

- **Navigation**: agent зөв файлаа олоход хэр амар байв? Файлуудын хооронд далд хамаарал байна уу? **Navigation pointer** (өөр файл руу заасан товч заалт) нэмбэл амар болох уу? _Хэзээ хэрэглэх_: session нэг мэдээлэл олоход их удсан бол.
- **Автомат шалгалт**: agent-ийн гаргасан алдааг барьж чадах автомат шалгалт байна уу? Linting, typing, test, файлын системийн linter? Эхлээд repo-гийн өөрийн шалгах командыг унш (`package.json`/build tool-ийн `lint`/`check` script, CI workflow). Ингэснээр аль хэдийн байгаа ч холбогдоогүй, эсвэл чимээгүй эвдэрсэн шалгалт өөрөө олдвор болно, түүнийг дахин зохиохгүй. **Guardrail** (хамгаалалтын автомат шалгалт) огт байхгүй repo (pre-commit hook ч, lint/typecheck/test командыг ажиллуулдаг CI job ч байхгүй) өөрөө олдвор: lint хийгддэггүй repo бол төвийг сахисан анхдагч төлөв биш, байнга алдаж буй боломж. _Хэзээ хэрэглэх_: agent автомат шалгалтаар барьж болох алдаа гаргасан, эсвэл repo-д огт guardrail байхгүй бол.
- **Кодын стандарт**: **reviewer agent**-д мөрдүүлэх шинэ дүрэм өгөх үү? Байгаа дүрмийг хасах эсвэл тодруулах уу? Эхлээд зөрчлийг ангил. **Механик** зөрчил (тогтсон синтакс загвар, хориглосон API, import-ийн хэлбэр, файлын байршлын дүрэм) заавал детерминист шалгалттай болно: repo-гийн өөрийн linter-т custom дүрэм, шинэ pre-commit hook, эсвэл шинэ CI job. Repo-гийн хэл, байгаа guardrail-аас хамаарч аль нь хамгийн хямд байна, түүнийг сонго. Дүрэм бичихийн оронд шалгалт хийхийг анхдагч болго. `CODING_STANDARDS.md`-г жинхэнэ **шүүлт шаардсан асуудалд** л үлдээ (файл хоорондын нийцэл, "эргэн тойрныхоо хэв маягтай таарч байна", ямар ч guardrail орлож чадахгүй бүх зүйл). _Хэзээ хэрэглэх_: reviewer agent алдааг барьж чадаагүй бол.
- **Global AGENTS.md**: кодын стандарт (эсвэл автомат шалгалт) руу шилжүүлэх ёстой чиглүүлэх заавар байна уу? _Хэзээ хэрэглэх_: AGENTS.md файл онцгой том бол (repo-д ЭСВЭЛ хэрэглэгчийн global хүрээнд).
- **Tool-ийн хэмнэлт**: agent хялбарчилж болох үнэтэй tool дуудлага хийсэн үү? Token-ийг онцгой үр ашиггүй зарцуулдаг custom хэрэгсэл (CLI, MCP) байна уу? _Хэзээ хэрэглэх_: agent үнэтэй tool дуудлага хийсэн бол.
- **No-op**: чиглүүлэх файлуудад agent-ийн зан төлөвийг огт өөрчилдөггүй заавар байгаа эсэхийг хай. _Хэзээ хэрэглэх_: чиглүүлэх файлууд том, эмх замбараагүй болсон бол.
- **Мэдээллийн хүртээмж**: agent-ийн мэдээлэл авах боломжийг нэмэх арга хай. Dev server-ийн log-ийг `tee`-ээр файлд давхар бичих, гуравдагч үйлчилгээнд зөвхөн унших эрх өгөх. _Хэзээ хэрэглэх_: чухал мэдээлэл agent-д хүрэхгүй байсан бол.
- **Дахин хэрэг болох сургамж**: agent амархан олдохооргүй шалтгаантай алдааг зассан, library эсвэл API-ийн онцлогийг тойрч гарсан, эсвэл төслийн заншлыг олж мэдсэн үү? Үүнийг skill эсвэл docs болгон хадгалахыг санал болго: асуудал, жинхэнэ шалтгаан, шийдэл. Үсгийн алдаа зэрэг өчүүхэн засвар, API түр унасан гэх мэт нэг удаагийн асуудлыг алгас. _Хэзээ хэрэглэх_: agent дахин тулгарч болох хэцүү асуудлыг шийдсэн бол.

4. Эдгээр боломжийг хэрэглэгчид хамгийн ноцтойгоос нь эхлэн дарааллаар нь танилцуул.

## Лавлах

### Хэрэгжүүлэлт ба Review

Бүх ажил хэрэгжүүлэлт, review гэсэн хоёр шатаар явдгийг сана. Хэрэгжүүлэгч agent хамгийн их **context-ийн ачаалалтай**. Тэр судлах, код бичих, алдааг debug хийх үүрэгтэй.

Review agent хамгийн бага context-ийн ачаалалтай: diff хүлээж авдаг тул судлах шаардлагагүй. Ихэнхдээ код бичих, debug хийх ч шаардлагагүй.

Тиймээс кодын стандартыг мөрдүүлэх үүрэг хэрэгжүүлэгч agent-д биш, review agent-д байх ёстой.

### Файлууд

Repo-д чамд ашиглах хэд хэдэн файл бий:

- `CLAUDE.md`/`AGENTS.md`: энэ repo дээр ажиллаж буй аль ч agent-ийн context window руу эдгээр файл ордог. Тэдгээрийг маш хэмнэлттэй, ихэвчлэн зөвхөн бусад файл руу заах **navigation pointer**-т хэрэглэ.
- `CODING_STANDARDS.md`: энэ файлыг хэрэгжүүлэлтийн үед биш, review-ийн үед уншдаг. Стандартын файл 1,000 мөрөөс урт болбол docs folder-ууд руу **navigation pointer** нэм.
- Docs: docs-ийг бусад файлаас заасан лавлах файл болгон ашигла. Шинийг бичихээсээ өмнө байгаа docs-ийг хай.
- Skill: skill-ийг docs-д (учир нь description нь agent-ийн context window-д ордог), эсвэл хэрэглэгчийн дууддаг командад ашигла. `agent-zaavar` skill-ийн зөвлөгөөг дага.
