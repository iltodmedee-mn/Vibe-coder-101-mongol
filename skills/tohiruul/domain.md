# Domain Docs

Engineering skill-үүд codebase-ийг судлахдаа энэ repo-гийн domain баримт бичгийг хэрхэн уншихыг тодорхойлно.

## Судлахаасаа өмнө эдгээрийг унш

- repo-гийн root дахь **`GLOSSARY.md`**, эсвэл
- root-д **`GLOSSARY-MAP.md`** байвал түүнийг: тэр нь context бүрт нэг `GLOSSARY.md` руу заана. Сэдэвт хамаарах бүрийг нь унш.
- **`docs/adr/`**: ажиллах гэж буй хэсэгт хамаарах ADR-уудыг унш. Multi-context repo-д context-ийн хүрээний шийдвэрүүдийг `src/<context>/docs/adr/`-аас бас шалга.

Эдгээр файлын аль нэг нь байхгүй бол **чимээгүй үргэлжлүүл**. Байхгүйг нь дурдахгүй, урьдчилан үүсгэхийг санал болгохгүй. `/domain-zagvar` skill (`/shalga-barimt` ба `/butets-saijruul`-аар дамжиж хүрдэг) нэр томъёо эсвэл шийдвэр үнэхээр шийдэгдэх үед тэдгээрийг тухай бүрт нь үүсгэдэг.

## Файлын бүтэц

Single-context repo (ихэнх repo):

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

Multi-context repo (root-д `GLOSSARY-MAP.md` байгаа):

```
/
├── GLOSSARY-MAP.md
├── docs/adr/                          ← бүх системд хамаарах шийдвэрүүд
└── src/
    ├── ordering/
    │   ├── GLOSSARY.md
    │   └── docs/adr/                  ← тухайн context-ийн шийдвэрүүд
    └── billing/
        ├── GLOSSARY.md
        └── docs/adr/
```

## `GLOSSARY.md`-ийн үгсийн санг хэрэглэ

Гаргаж буй зүйлдээ (issue-ийн гарчиг, refactor-ийн санал, таамаглал, test-ийн нэр) domain-ий ойлголт нэрлэхдээ `GLOSSARY.md`-д тодорхойлсон нэр томъёог хэрэглэ. `GLOSSARY.md`-д зайлсхийхээр тэмдэглэсэн ижил утгатай үгсийн оронд тодорхойлсон нэрийг нь барь.

Хэрэгтэй ойлголт чинь `GLOSSARY.md`-д хараахан байхгүй бол энэ нь дохио: чи төслийн хэрэглэдэггүй хэл зохиож байна (дахин бод), эсвэл жинхэнэ цоорхой байна (`/domain-zagvar`-д тэмдэглэ).
