Энэ skill одоогийн ярианы context болон codebase-ийн талаарх ойлголтоос spec гаргана. Хэрэглэгчээс ярилцлага бүү ав; мэдэж байгаа зүйлээ л нэгтгэ.

Issue tracker болон triage label-ийн нэрс чамд өгөгдсөн байх ёстой. Үгүй бол хэрэглэгчид `/tohiruul` ажиллуулахыг хэл.

## Явц

1. Codebase-ийн одоогийн байдлыг ойлгохын тулд repo-г судал (хэрэв хараахан судлаагүй бол). Spec даяар төслийн domain glossary-ийн үгсийг ашигла, хөндөж буй хэсгийн ADR-уудыг хүндэтгэ.

2. Feature-ийг ямар **seam** (кодын хэсгийг тусгаарлаж, гаднаас нь test хийж болох зааг) дээр test хийхээ тоймло. Шинэ seam-ээс одоо байгааг нь илүүд үз. Аль болох өндөр seam ашигла. Шинэ seam хэрэгтэй бол аль болох дээд цэгт санал болго. Codebase даяар seam цөөн байх тусам сайн: хамгийн зөв нь ганцхан.

Эдгээр seam хэрэглэгчийн хүлээлттэй таарч байгаа эсэхийг түүнээс асууж шалга.

3. Доорх загвараар spec-ээ бич, тэгээд төслийн issue tracker-т нийтэл. `ready-for-agent` triage label тавь: нэмэлт triage хэрэггүй.

**Бүү зохио.** Ярианд гараагүй, codebase-ээс ч олдоогүй зүйлийг итгэмээр сонсогдох шаардлага болгож бүү нэм. Оронд нь тэр газарт `TBD: <яаж тодруулах>` гэж бич, тэгээд "Нэмэлт тэмдэглэл" хэсэгт нээлттэй асуулт болгож жагсаа. Хүсэлт codebase-ийн одоо байгаа хязгаарлалттай зөрчилдвөл зөөлрүүлэлгүй, тодорхой хэл.

## Хэрэгжүүлэлтийн шийдвэрүүд

Гаргасан хэрэгжүүлэлтийн шийдвэрүүдийн жагсаалт. Үүнд дараах зүйлс орж болно:

- Шинээр бүтээх/өөрчлөх module-ууд
- Өөрчлөгдөх module-уудын interface
- Хэрэглэгчийн өгсөн техникийн тодруулга
- Архитектурын шийдвэрүүд
- Schema-ийн өөрчлөлт
- API гэрээ (contract)
- Тодорхой харилцан үйлчлэлүүд

Тодорхой файлын зам, кодын хэсэг бүү оруул. Тэд маш хурдан хуучирч болно.

Үл хамаарах зүйл: хэрэв prototype нь үгээр хэлснээс илүү нарийн шийдвэр агуулсан код (state machine, reducer, schema, type-ийн хэлбэр) гаргасан бол түүнийг холбогдох шийдвэрийн дотор оруулж, prototype-оос гарсныг товч тэмдэглэ. Ажилладаг demo биш, шийдвэр агуулсан хэсгийг л үлдээ: зөвхөн чухал хэсгүүдийг.

## Test-ийн шийдвэрүүд

Гаргасан test-ийн шийдвэрүүдийн жагсаалт. Үүнд:

- Сайн test гэж юу болохын тайлбар (дотоод хэрэгжүүлэлтийг биш, зөвхөн гаднаас харагдах үйлдлийг test хийнэ)
- Аль module-уудыг test хийх
- Өмнөх жишээ (codebase дахь ижил төрлийн test-үүд)

## Хамрах хүрээнээс гадуур

Энэ spec-д хамаарахгүй зүйлсийн тайлбар, тус бүр яагаад гадуур үлдсэнийг товч.
