# Prototype

Prototype бол **асуултад хариулдаг, хаях зориулалттай код**. Асуулт нь хэлбэрийг шийднэ.

## Салаагаа сонго

Хэрэглэгчийн prompt, эргэн тойрны код, эсвэл хэрэглэгч хажууд байвал асууж, аль асуултад хариулж байгааг тодорхойл:

- **"Энэ логик / state model зөв санагдаж байна уу?"** → [LOGIC.md](LOGIC.md). Цаасан дээр бодоход хэцүү тохиолдлуудаар state machine-ийг давуулж үзүүлдэг, код мэдэхгүй хүн ч удирдаж чадах, хуваалцаж болох ганц HTML файл бүтээ (чөлөөт товчнууд дээр нь tab-аар хуваасан хөтөлсөн walkthrough-ууд).
- **"Энэ ямар харагдах ёстой вэ?"** → [UI.md](UI.md). Нэг route дээр эрс өөр хэд хэдэн UI хувилбар үүсгэ. URL search param болон доод талын хөвөгч мөрөөр хооронд нь сэлгэнэ.

Хоёр салаа тэс өөр бүтээгдэхүүн гаргадаг тул буруу сонговол prototype бүхэлдээ дэмий болно. Асуулт үнэхээр хоёрдмол утгатай, хэрэглэгч хажууд байхгүй бол эргэн тойрны кодод аль нь илүү тохирохыг сонго (backend module → логик; хуудас эсвэл component → UI), мөн prototype-ийн дээд хэсэгт энэ таамаглалаа бич.

## Хоёуланд нь хамаарах дүрэм

1. **Эхний өдрөөсөө хаях зориулалттай, тийм гэдэг нь тодорхой тэмдэглэгдсэн.** Prototype-ийн кодыг бодитоор ашиглагдах газрын ойролцоо (prototype хийж буй module эсвэл хуудасных нь хажууд) байрлуул, тэгвэл контекст нь ойлгомжтой. Гэхдээ санамсаргүй уншигч production биш prototype гэдгийг харахаар нэрлэ. Хаях UI route-д төслийн одоо байгаа routing-ийн дүрмийг дага; шинэ дээд түвшний бүтэц бүү зохио.
2. **Ажиллуулахад маш амархан.** UI prototype нь төслийн task runner-ийн нэг командаар асна: `pnpm <name>`, `python <path>`, `bun <path>` гэх мэт. Логикийн demo бол хэрэглэгч хоёр дарж нээдэг ганц HTML файл. Аль ч тохиолдолд асаахад бодох юм байхгүй.
3. **Анхдагчаар хадгалалт (persistence) байхгүй.** State санах ойд амьдарна. Persistence бол prototype-ийн _шалгаж_ буй зүйл, түүнээс хамаарах зүйл биш. Асуулт тодорхойгоор database-тэй холбоотой бол "PROTOTYPE, wipe me" гэж тодорхой нэрлэсэн түр DB эсвэл local файл руу ханд.
4. **Өнгөлгөөг алгас.** Test байхгүй, prototype-ийг _ажиллуулж_ чадахаас өөр алдааны боловсруулалт байхгүй, abstraction байхгүй. Гол нь хурдан ямар нэг юм сурах.
5. **State-ийг ил гарга.** Үйлдэл бүрийн дараа (логик) эсвэл хувилбар солих бүрт (UI) холбогдох state-ийг бүтнээр нь хэвлэж эсвэл харуулж, юу өөрчлөгдсөнийг хэрэглэгч харж чаддаг бай.
6. **Дуусахаар нь хадгал.** Батлагдсан шийдвэрийг бодит код руу оруул, дараа нь prototype-ийг өөрийг нь **анхдагч эх сурвалж** (primary source) болгож хадгал: main-аас гадуур, хаях branch руу commit хий, мөн хэрэгжүүлэлтийн issue дээр тэр branch руу заасан заагч (context pointer) үлдээ. Хариултыг ч (дүгнэлт болон түүний шийдсэн асуулт) issue эсвэл commit-д хадгал. Main branch зөвхөн батлагдсан шийдвэрийг хадгална.
